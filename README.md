# TeamAgents · DSH 插件 MVP

一个从零实现、独立命名的多 Agent 协作插件。产品方向参考 [limuyang2/agent-team](https://github.com/limuyang2/agent-team)，没有复制其源码。

**目标宿主：DeepSeek Harness 0.2.1-rc.2，Web / Desktop 的 Web 界面。** 不是参考插件的替换包，也不承诺兼容其较早版本的 API 或存档。

## v0.2.0：设置页自己配置

安装/更新插件后，打开 DSH 的 **设置 → TeamAgents**。入口追加在现有设置导航末尾，也就是截图中“插件市场”下方标记的位置；不是插件市场中的页面，也不替换设置窗口。

1. 先选中一个已有的普通主会话。页面跟随当前会话，每个主会话一个团队；没有选中会话时会提示选择。
2. 编辑**团队名称、目标、最大并发数**，增删**成员、角色、指令**，配置**任务、负责人、前置任务和写入范围**。也可以点“载入只读分析示例”填充草稿再修改。
3. 点 **保存计划**。这一步只保存整份草稿，不启动成员、不调用模型，也不需要给主 Agent 发消息。
4. 在“执行”区核对已保存版本，勾选费用/执行确认，再点 **开始**。成员首次创建时继承主会话当前选择的模型；尚未进行过模型请求时使用 GUI 已选/默认模型，不要求先发送一条占位消息。
5. 在同页查看进度、输出和错误，点 **停止团队** 或 **准备重试**。准备重试不执行任务，仍需确认新版本后点“开始”。

注意：v0.2.0 的设置操作仅允许 DSH 已认证的 **Host owner**。成员子会话、归档会话或无权限访问不会获得管理能力。界面确认框用于防误触；权限由宿主原生 Gateway/Remote 调用上下文校验，不能靠传入 `sessionId` 或确认字符串伪造。

未执行过的计划可以整体修改；发生过任何执行尝试后，配置锁定为只读以保留历史。若需要重新编排，使用新的主会话。其他标签页或聊天修改了计划时，表单保留本地编辑并提示冲突，须明确放弃并重新加载，不能覆盖新版本。

## 已实现

- **可视化设置页**：独立的 `settings.section` 导航入口、成员/任务表单、依赖校验、保存/确认启动/停止/重试，支持中英文及宿主主题。
- **先规划，后执行**：保存草稿不调用模型。设置页通过明确的用户动作启动；聊天工具仍要求之后的人类回合明确批准。两条入口都校验计划 revision。
- **任务 DAG**：验证依赖存在、成员存在及无环；只有成功完成的前置任务会放行后续任务。
- **受控并行**：每个成员同一时间只执行一个任务；团队并发数 1–8，默认 3；声明的写入路径存在祖先/后代重叠时串行执行。
- **成员会话复用**：使用官方 Agent factory 创建、恢复独立成员会话；通过官方 delegation helpers 继承模型路由、组合和委派权限策略，不复制 API key。每次任务从主会话的原始工作区根目录开始，避免上一个任务的 `cd` 改变写入范围的含义。
- **协作消息**：发送者由真实调用会话确定，不能伪造；运行中的成员在后续 step 接收消息，空闲成员在下一个任务收到积压消息，不因消息自动启动模型。
- **失败与恢复**：超时/中断不记为成功；停止等待协作式退出，不回滚文件；重试生成新 attempt；迟到结果不能覆盖已撤销任务。宿主重启后暂停团队，不自动续跑。
- **会话面板**：输入区域下方的可折叠只读面板，显示成员、依赖、任务状态、结果和消息；支持中英文，跟随 DSH 主题。

## 本地开发

需要 Node.js 22+、npm，以及上述版本的 DSH。开发依赖从 npm 获取；运行插件需要宿主提供对应 SDK 服务。

```bash
npm ci --ignore-scripts
npm run check
npm pack
```

`npm run check` 执行类型检查、单元测试和宿主/浏览器构建。安装过程不运行第三方 lifecycle scripts；esbuild 使用平台可选二进制包。

SDK 和 Zod 使用已核对的版本。不要只升级某个 DSH peer，或将 Zod 改成任意最新版：它的 schema 类型需要与宿主 SDK 使用的版本兼容。

## 安装（需要你自己确认后操作）

**本项目的构建、测试不会安装插件、改变 DSH profile、启动替代服务器或调用付费模型。**

先在本仓库根目录执行 `npm ci --ignore-scripts && npm run check`，确保已经生成产物，然后优先在 DSH 的插件管理界面中安装仓库所在目录，或安装 `npm pack` 产生的压缩包。

如果使用 npm CLI 的 **web profile**，可在你确认后运行（把 `<仓库路径>` 换成实际绝对路径）：

```bash
npx @deepseek-ai/dsh@0.2.1-rc.2 plugin --profile web add <仓库路径>
```

不要用这条命令假定会修改当前 **Desktop profile**：Desktop 使用自己绑定的运行时和 profile，应通过桌面应用的插件管理功能操作。这个仓库仍为 `private: true`，不会自动发布到 npm。

安装后按宿主提示重启/刷新页面。修改本地代码后须重新构建；替换已加载的模块通常需要重启宿主并刷新页面。这里没有启动 DSH 源码的 `dev:web` watcher，**不承诺热更新**。

### 安装后人工验收

1. 更新到 v0.2.0 后重启宿主并刷新页面，确认设置左侧出现 **TeamAgents**；旧的 v0.1.0 包只有对话区面板，没有此入口。
2. 选中一个普通主会话，进入设置页，载入只读示例并修改名称；点击“保存计划”，确认没有成员模型请求。
3. 勾选保存版本的确认框再点“开始”。两个独立分析任务可并行，汇总任务等待它们成功后运行。真实模型调用可能产生费用。
4. 检查设置页、输入区下方的只读面板和 `team_agents_status` 一致。切换会话不能显示或保存到前一个会话；未保存表单不能覆盖更新后的计划。
5. 测试停止、失败和准备重试；重启宿主后运行中团队应暂停。确认归档/子会话和非 owner 调用被拒绝。

仓库中的无模型测试不能替代实际宿主加载、真实模型调用及浏览器视觉验收；这些需要在安装后执行。

## 可选：继续用聊天控制

设置页已经可以独立配置和操作；以下聊天方式仍然保留。给主 Agent：

> 使用 TeamAgents 插件。目标是分析当前项目：researcher 检查架构，tester 检查测试覆盖；两者只读并行，reviewer 等待前两项完成后汇总风险。先给我团队和任务计划，不要执行。

看过计划后，在**下一条消息**说：

> 批准这份计划，开始执行。

需要停止时：

> 停止 TeamAgents 团队，等成员退出。告诉我哪些任务可能留下了部分改动。

### 工具

| 工具 | 用途 |
| --- | --- |
| `team_agents_create` | 当前主会话创建一个草稿团队 |
| `team_agents_add_member` | 添加成员和角色，不启动模型 |
| `team_agents_add_task` | 添加任务、负责人、依赖、写入范围 |
| `team_agents_update_task` | 停止状态下编辑尚未尝试的 pending 任务 |
| `team_agents_start` | 校验 `expectedRevision` 后启动；`confirmation` 必须引用真实用户批准 |
| `team_agents_status` | 查看本会话团队；成员只能查看所属团队 |
| `team_agents_message` | 团队内归属明确的持久化消息 |
| `team_agents_stop` | 暂停并等待模型协作式退出 |
| `team_agents_retry_task` | 失败任务重新置为待执行；仍需重新批准并启动 |

添加任务时按依赖的拓扑顺序操作，例如先添加 `inspect-api` 和 `inspect-tests`，再添加依赖二者的 `summary`。计划运行时不可编辑；先停止。每个主会话一个团队，另一个团队使用新会话。

## 架构

```text
设置页 → DSH 原生 Remote/Gateway（owner + session 资源校验）┐
                                                       ├→ TeamEngine → storage domain
主会话 tools（保留）───────────────────────────────────────┘
                    │
                    ├─ 依赖 / 并发 / 成员占用 / 写入范围调度
                    └─ DshTeamDriver → 独立持久化成员 Agent

状态变化 → ignorable plugin snapshot record → session projection
                                             ↓
                                DSH 现有会话通道 → React Slot 面板
```

| 模块 | 职责 |
| --- | --- |
| [模型](src/model.ts) | Zod 校验、DAG 验证、路径重叠规则 |
| [调度器](src/engine.ts) | 串行状态提交、并行执行、attempt 防迟到覆盖、恢复 |
| [运行时适配](src/runtime.ts) | 官方 Agent create/resume、权限继承、退出及结果采集 |
| [宿主入口](src/index.ts) | 工具注册、真实调用者识别、生命周期清理 |
| [投影](src/projection.ts) | 可丢弃、可重建的 UI 快照；隔离 fork 中继承的旧团队 |
| [客户端入口](src/client.tsx) / [面板](src/dashboard.tsx) | DSH Slot 注册、会话级响应式 UI |
| [设置页](src/settings-page.tsx) / [设置接入](src/settings-integration.tsx) | 表单、确认流程、导航、当前会话绑定、投影更新 |
| [Remote 服务](src/remote.ts) / [客户端](src/remote-client.ts) / [协议](src/remote-contract.ts) | 原生认证、资源归属、严格参数校验及生命周期 |

### 数据与边界

- 权威状态保存在 DSH storage domain `dsh_team_agents` 的 `teams` 表，按主会话 ID 隔离；具体路径和介质由宿主 storage backend 决定。不在工作仓库写 `.agent-teams`，也不修改参考插件的数据。
- 成员对话走 DSH 原有会话持久化。面板数据走宿主现有会话读取授权；没有新建未鉴权路由，没有独立服务器，也没有浏览器端 API key。
- 面板使用 0.2.1-rc.2 的 experimental ignorable plugin records，不是自行扩展必需的 session event catalog。记录即使在迁移中被丢弃，也能在主会话重新加载时从权威状态重建。
- 状态包含任务描述、消息和文本结果，属于敏感会话数据。没有额外加密层；请按 DSH 会话数据保护它。不要在任务/消息中粘贴密钥。
- 写入范围是调度与提示约定，**不是文件系统隔离或安全边界**；没有自动 worktree、Git 合并或回滚。模型必须仍遵守宿主权限。停止不能撤销已经完成的外部操作。
- 官方委派策略将成员的 approval policy 固定为 `never`，需要扩大权限的操作应交回主 Agent。成员不能使用主 Agent 中不存在或实现不同的工具。任意父会话局部 hook 不会自动克隆；自定义部署应验证自己的委派策略。
- **设置页控制**通过宿主既有原生 `/api` 的 Typert Remote 通道，注册 `teamAgents/read`、`save`、`start`、`stop`、`retry`，每个方法声明 Session 资源并再次校验真实 Host-owner 调用上下文。没有新建 HTTP 路由或非 owner 授权策略；同进程直接调用、伪造 principal、过期会话、跨工作区和子会话均被拒绝。读取/保存可处理冷会话；仅明确的开始动作通过宿主公共 API 激活主 Agent。
- **聊天工具批准**仍是聊天协议 + 草稿/版本门禁，`confirmation` 不是认证凭据，也不等同于设置页的原生授权。部署方如需仅允许 UI 启动，应在工具策略中禁用 `team_agents_start`。已执行的外部操作不可回滚；关闭设置页不会自动停止已经启动的团队。
- 并发上限按团队计算，多个主会话可能并行运行更多模型；请控制成本。任务默认 20 分钟协作式超时，最多 12 个成员、200 个任务、500 条待处理/保留消息；结果快照保留前 50,000 字符，完整对话留在成员会话中。
- 正常结束仅表示成员 turn 完成并给出报告，**不代表独立审核已通过**。生产部署、人类授权、验收标准仍由使用者负责。
