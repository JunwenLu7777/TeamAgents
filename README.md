# TeamAgents · Agent 配置库 + 会话调度

一个独立命名的 DeepSeek Harness 多 Agent 协作插件。产品方向参考 [limuyang2/agent-team](https://github.com/limuyang2/agent-team)，没有复制其源码。

**目标宿主：DeepSeek Harness 0.2.1-rc.3，Web / Desktop 的 Web 界面。** 当前版本 **0.6.1**，不是参考插件的替换包，不承诺较早 SDK 或存档兼容性。

## v0.6.1：修复未启动成员误报断线

尚未创建成员会话时，正常的单次响应显示 **快照已读取 · 暂无成员会话**，可用 **刷新快照** 重新读取，不再显示断线或过期状态警告。真正的连接失败、活动会话流结束和任务错误仍明确展示；成员会话随后创建时，会切换到新的实时订阅。刷新快照不会启动模型或任务。

## v0.4.1：运行面板移至顶部会话标签

TeamAgents 现在通过宿主公开的 `conversation.view` 接口，追加到顶部会话标签栏末尾；在标准界面中位于 **对话 / 轨迹 / 上下文 / 编队** 之后。不修改或替换内置“编队”，也不再向输入框下方的 composer dock 注册面板。

点击 **TeamAgents** 后在会话正文中查看默认展开的团队详情，沿用宿主正文滚动；切回“对话”不会占用输入区或清空聊天草稿。没有团队时显示说明，不自动创建或执行团队。空白会话的标签显示遵循宿主原有规则。

**设置 → TeamAgents** 仍然只管理全局 Agent 配置库；目标、计划和执行确认仍在会话中完成。更新此版本不会修改已保存配置、已有团队或测试草稿。

## v0.5.0：运行记录导出

在有团队记录的会话顶部打开 **TeamAgents** 标签，找到 **运行记录导出**：

1. 选择 **Markdown**（便于阅读）或 **JSON**（便于后续处理），默认 Markdown。
2. 默认不包含团队消息；需要时明确勾选 **包含已保留的团队消息**，并检查隐私提醒。
3. 点击 **下载导出文件**。文件通过浏览器下载到本机，不上传到外部服务，也不接受任意宿主输出路径。

导出包括：团队目标与状态、成员及其配置模型、任务依赖/写入范围/状态/尝试次数、仍保留的开始结束时间和输出/错误，以及 `schemaVersion: 1`、`sourceRevision`、`exportedAt`。文件名使用安全的团队标识、版本和时间，不使用原始团队名称构造路径。

**这是当前保留的快照，不是完整运行历史。** 重试会清除前一次结果和时间，输出可能已被引擎截断；导出不能恢复它们，也不包含逐 token 对话。继承模型标记为继承，不冒充执行时模型审计。正在运行、暂停、受阻、失败任务和空任务计划都可以如实导出；没有团队时不生成伪造空报告。

默认排除成员指令、全局 Agent 库、工作区标识、成员内部会话/attempt 标识；不会读取环境变量或凭据。**任务描述、输出、错误和主动包含的消息本身仍可能有敏感内容，不做自动脱敏保证，请在分享前检查。** 消息仅指当前团队保留的 mailbox，最多 500 条，不是其他会话或完整聊天记录。

最终文件上限为 **8 MiB UTF-8**，超限明确报错，不静默截断或下载半份文件。可先取消包含消息后重试；若仍超限，此版不提供分页/流式导出。8 MiB 是文件内容上限，不是原生传输层容量承诺，外层 JSON 转义会增加响应大小。

页面只在明确点击后导出，导出不会创建 Agent、启动模型或修改任务状态/版本。会话切换、权限失效或取消后不会下载晚到的旧会话数据。工具 `team_agents_export_run` 也支持同一只读操作，返回文件名、MIME、文本内容和来源元数据；它本身不写宿主文件，工具结果可能留在聊天记录中。

如果已安装的旧包没有导出按钮，需要另行构建、打包、更新插件并按宿主提示刷新；仓库中的源码改动不会自动替换已安装包。

## v0.6.0：成员执行过程

在 **TeamAgents** 标签的成员卡片点击 **查看执行过程**，下方展开该成员的只读详情：

- 当前分配任务、配置模型、最近一轮耗时和最近活动时间。
- 接收模型公开文本的实时预览；工具调用发出后的参数、结果、错误及工具耗时，也支持 `run_code` 内的子工具记录。
- 最近执行记录与失败原因；超时任务直接显示 `Task deadline exceeded`，不再只把失败成员标成“空闲”。
- 加载、已连接、断线、无会话等状态；断线后明确标为最后观测数据，耗时冻结，点击 **重新连接** 重新读取基线。

一次只查看一个成员。选择其他成员、关闭详情、切回其他会话/标签或失去查看权限，会取消原订阅。**查看和重连都不会创建/恢复 Agent、派发提示词、启动模型或修改任务状态。** 没有开始过的成员显示“尚未创建成员会话”和正常的“快照已读取”状态，可点击 **刷新快照** 重新读取，不会将正常单次响应误报成断线；会话创建前的任务错误仍会显示。冷历史可以读取，无须先运行一次任务。这里不提供成员输入框、重试或 Start 按钮；现有整队停止、导出与配置库功能不变。

实现参考“编队”的按需查看体验，但不会伪造内置 continuable 子代理 descriptor。通过宿主公开 `sessionController.inspect`、`session/event`、`agent/assistant-stream` 读取数据，经过 `teamAgents/watchMember` 原生流式 Remote 返回白名单视图。服务端检查真实 Host-owner 调用、父团队绑定、子会话来源/父子关系、工作区、归档状态及活跃 Agent 所有权；调用者只能提交主会话和成员名，不能指定任意子会话或文件路径。

### 显示范围与限制

- **不转发**系统/用户/开发者提示词、原始模型请求、私有推理、附件/图片或 opaque provider metadata。只读文本预览会屏蔽常见凭据字段与 token 形式，但不能保证业务文本完全脱敏，分享截图前仍须检查。
- 展示至多 80 条最近活动，单段预览最多 6,000 字符，记录文本总预算 18,000 字符，单帧最多 192 KiB；超出明确提示省略，不声称完整会话日志。尚不提供历史分页或大文本下载。
- 通过事件推送更新，不反复轮询 Remote。服务器每两秒检查一次仍在打开的订阅权限，但不重发未变化的历史；界面仅在查看运行中的成员时本地推进耗时。
- 打开前已经发出的实时文本来自有界的进程内缓存；热加载中途或缓存淘汰可能缺少前缀，完成后的持久化文本可在记录中查看（仍受预览上限约束）。未持久化的瞬时输出不保证重启后回放。
- 活跃 Session 被替换、释放或冷会话重新变为活跃时，旧观察会结束；明确点“重新连接”获取新基线，不悄悄继续读取旧实例。
- 此功能不修改旧团队状态，也不把旧的超时任务伪装为完成；配置模型不等同于执行时费用或模型用量审计。

原生 Gateway 的授权/流式契约、合成历史与实时事件、取消清理均有无模型测试；桌面和窄屏浏览器夹具使用模拟流，不访问当前登录的 DSH 或真实模型。安装后的真实长时间流连接仍需单独验收；源码构建不会自动更新已安装的压缩包。

## 配置与执行分开

| 位置 | 做什么 | 不做什么 |
| --- | --- | --- |
| **设置 → TeamAgents** | 管理可复用 Agent 的名称、角色、工作指令、模型与启用状态 | 不填写目标、任务或并发数；不创建会话、团队；不启动模型 |
| **普通主会话** | 用户提出具体目标，主 Agent 选择已保存配置、编排任务并请求执行确认 | 不要求用户回设置页重复填写目标 |
| **会话顶部的 TeamAgents 标签** | 查看本次目标、成员、任务、结果与消息；显式停止团队或下载运行快照 | 不保存全局配置，不提供自动启动入口 |

配置库属于当前 Harness 宿主，不随当前会话或工作区切换。没有选中会话，也可以配置 Agent。**保存 Agent 配置不等于执行任务。**

## 1. 配好 Agent

打开 **设置 → TeamAgents**：

1. 从 9 个角色模板添加 Agent：架构师、前端、后端、测试、UI 设计、数据库、产品经理、DevOps、安全评审；也可以添加自定义 Agent。
2. 编辑名称，展开修改角色和工作指令。名称使用唯一的小写连字符格式，最长 40 字符，`captain` 为保留名称。同模板重复添加会生成不同名称。
3. 为每个 Agent 选择 Harness 中已配置的模型，或保留 **继承调用会话的模型**。
4. 设置 **允许在会话中选用**，然后点 **保存 Agent 配置**。

初始配置库为空，模板只是添加草稿的快捷方式，不会自动保存。配置库最多保存 100 个 Agent；单次团队最多选择 12 个。停用或移除只影响之后从配置库的选用，不会停止或改写已有会话团队。

设置页不轮询，也不创建任何 Agent 会话。跨窗口保存使用库版本号做比较并写入：发生冲突时保留本地编辑，明确重新加载后再保存，不能静默覆盖别的窗口。

### 模型选择

- 模型目录来自宿主已注册提供方公布的模型，按提供方分组。目录可用不代表凭据、余额或服务连通性已经验证。
- 仅保存提供方与模型标识，不复制 API Key、端点或连接配置。
- 保存时校验已启用 Agent 的显式模型；不可用时可换选模型、继承主会话，或停用该配置。已停用配置可以保留原有失效模型。
- 创建会话团队时复制配置快照；启动和任务分发时再核对显式模型，不会自动改用另一个模型。
- 未选模型的成员保留继承主会话的行为；显式模型采用自己的默认 reasoning effort，不强加主会话旧值。
- 已执行团队的成员配置不能重写。要使用新的配置，请新建主会话并重新选择 Agent。

## 2. 在会话中提出需求

例如对主 Agent 说：

> 使用 TeamAgents 配置库中已启用的架构师、前端和测试 Agent，分析当前项目的这个需求。先读取已有配置，给我成员分工、任务依赖和写入范围，不要执行。

主 Agent 会先读取库版本和已配置 Agent，选择适合的成员，把**这次用户需求**作为团队目标，并在会话里给出计划。看过计划后，在**下一条消息**明确批准：

> 批准这份计划，开始执行。

需要停止时，可以使用会话面板的 **停止团队**，或在会话中说：

> 停止 TeamAgents 团队，等成员退出，告诉我哪些任务可能留下了部分改动。

任务失败后先检查部分修改，再准备重试；重试仍需要新版本的明确批准，不会自动开始。关闭设置页也不会停止正在运行的会话团队。

### 会话工具

| 工具 | 用途 |
| --- | --- |
| `team_agents_list_agents` | 只读列出宿主配置库及版本号，不创建团队 |
| `team_agents_create` | 以本次会话目标创建草稿；可通过 `agents` 名称列表和 `libraryRevision` 原子复制已启用配置 |
| `team_agents_add_member` | 兼容保留：显式添加本次团队的自定义成员，不改全局库 |
| `team_agents_add_task` | 分配负责人、依赖和写入范围，不执行 |
| `team_agents_update_task` | 编辑从未尝试的待执行任务 |
| `team_agents_start` | 核对计划版本后启动；必须引用后续人类回合的真实批准 |
| `team_agents_status` | 查看本会话团队；成员只能查看所属团队 |
| `team_agents_export_run` | 主会话只读导出当前保留快照；`format` 为 `markdown`/`json`，`includeMessages` 默认 false |
| `team_agents_message` | 按真实发送者身份传递消息 |
| `team_agents_stop` | 停止并等待协作式退出，不回滚文件 |
| `team_agents_retry_task` | 为失败任务准备新 attempt，仍需重新批准 |

`agents` 与 `libraryRevision` 必须一起提供，版本来自刚读取的库，不能猜测。不存在、已停用、重复或超过 12 个的选择都会拒绝，且不会留下半个团队。库版本在选择期间发生变化时需重新读取。原有不带配置库参数的创建方式保留兼容；配置库的停用限制针对库选用，不是禁止手动创建同名自定义成员的权限机制。

当前仍是**每个主会话一个团队执行记录**。另一个独立目标使用新的主会话；不是在设置页重建 Agent 配置。任务按依赖拓扑顺序添加；并发上限 1–8、默认 3，由本次会话计划决定。

## 从 v0.2 / v0.3 更新

- 旧的 `dsh_team_agents / teams` 数据保留原域、原版本和原内容；历史目标、成员模型、任务和结果不会被转换或删除。
- 新配置库存入独立的 `dsh_team_agent_library / libraries / default`，与任何会话执行记录分离。
- 不会自动把不同旧会话的成员合并为全局配置，避免名称冲突或无意共享会话专属指令。首次使用新库时请添加并保存所需 Agent。
- 已有会话团队继续通过会话工具和面板查看/控制；配置库编辑不会改写它们。宿主重启仍暂停未完成执行，不自动恢复模型工作。
- v0.3 已引入成员模型字段；写入后不要直接降级到严格旧 schema 的 v0.2.0。降级前需另行备份与迁移数据。

## 构建、测试与安装

需要 Node.js 22+、npm 和上述宿主版本。在本仓库运行：

```bash
npm ci --ignore-scripts
npm run check
npm run test:layout
npm pack --ignore-scripts
```

- `check`：类型检查、单元测试、宿主 ESM 与浏览器 lazy-factory 构建。
- `test:layout`：使用本机 Chrome/Chromium，`CHROME_BIN` 可指定绝对可执行路径；不安装浏览器、不启动服务器，无浏览器时明确失败。包含 6 个配置库场景（无会话编辑、模拟 CAS 保存等）及 3 个顶部标签场景（桌面、窄屏、空团队）。顶部标签用真实 SlotCore 和插件注册，外壳为隔离模拟，验证顺序、选择/切换、输入区不占位、草稿保留与正文滚动。不会访问已登录 GUI、真实会话、凭据或模型。报告与截图输出至 `lib/layout-check/`，不进入安装包；它们不等于真实 Desktop 的视觉复验。
- 导出测试覆盖 serializer/客户端一致性、真实 SDK Gateway 与合成 Peer 的权限正反例、冷会话不激活、取消/切换隔离、UTF-8 精确边界、重试后不恢复旧数据和无状态副作用。多兆字节响应做了原生 codec 加 JSON 编解码回环，不等于真实 HTTP/桌面传输实测。
- 浏览器导出夹具使用真实 Blob/ObjectURL 与资源回收，但拦截下载点击，不写真实文件；不等于操作系统下载对话框或当前已登录 Desktop 的端到端验收。真实大文件传输及落盘需要更新安装后另行验证，不能通过调高宿主限制或绕过权限来规避失败。
- SDK 和 Zod 均固定在已核对的版本，不要单独升级某个 DSH peer 或用不兼容 Zod 替换。

安装包由上述 `npm pack` 命令生成（当前版本 v0.6.1）。在当前 Desktop 的主侧栏打开 **插件 → 添加插件 → 安装第三方插件**，输入安装包的绝对路径，安装后确认启用。按宿主提示决定是否重启，再刷新原界面。

**构建和测试不会安装插件、修改 Desktop profile、启动替代服务器或运行真实模型。** 重构建仓库不会自动替换此前安装的压缩包，不承诺开发热更新。不要用另一个 `web` profile 的安装命令假定会更新 Desktop；Desktop 使用自己的运行时与配置。

### 安装后检查

1. 不选择会话直接打开设置，确认只有 Agent 配置，没有目标、任务和启动按钮。
2. 添加不同角色、选择模型、停用一个配置并保存；关闭重开设置仍能读取。切换会话不切换配置库。
3. 在两个窗口同时编辑，确认旧版本保存会报冲突且保留草稿；目录异常不应清空选择或偷偷换模型。
4. 在有聊天记录的会话中确认顶部“编队”右侧出现 **TeamAgents**，输入框下方不再显示旧面板；切换标签后草稿保留，团队详情在正文正常滚动。
5. 在会话里要求使用已启用 Agent，确认先展示计划而非自动执行；配置库修改不改变已创建团队快照。
6. 经明确批准后再验证真实模型路由和面板停止。**无模型测试和隔离截图不等于已安装 Desktop 或真实模型调用的完整验收。**

## 架构与权限

```text
设置页（root scope，无 Session）
  → teamAgentLibrary/read | models | save（Host owner）
  → AgentLibraryStore → 独立配置库 domain

用户会话目标 → list_agents → 选配置快照 → 创建草稿 + 编排任务
  → 后续用户确认 → TeamEngine → DshTeamDriver → 成员会话
  → session projection → 会话面板（查看 / 明确停止）
```

| 模块 | 职责 |
| --- | --- |
| [配置库模型](<src/library-model.ts>) / [存储](<src/agent-library.ts>) | 纯配置、唯一名称、启用状态、库版本 CAS、深拷贝选择 |
| [配置库 Remote](<src/library-remote.ts>) / [协议](<src/library-remote-contract.ts>) / [客户端](<src/library-remote-client.ts>) | 全局资源、真实 owner 身份、严格参数与取消检查；没有执行方法 |
| [设置页](<src/settings-page.tsx>) / [接入](<src/settings-integration.tsx>) | root-scoped Agent 编辑，无 SessionProvider 或会话投影 |

- 配置库 Remote 仅接受真实 Gateway Host-owner 调用；没有 SessionId 参数，也不能靠传入伪造身份绕过。客户端使用宿主全局 `useRemoteAccess`，服务端仍再次校验。成员工具不能读取或写入全局库；主 Agent 的库工具仅只读/选择，没有改配置入口。
- 保存前及队列提交前检查取消、连接撤销和服务生命周期；宿主存储 `put` 已开始后没有撤销/回滚接口，卸载会等待其完成，不能把取消等同于撤销已准入写入。
- 原有会话 Remote 继续校验 owner、真实 Session 资源与工作区，保留历史客户端兼容；新设置页只挂载配置库操作。没有新增未鉴权 HTTP 路由或独立服务。
- 聊天 `confirmation` 不是认证凭据。必须对应之后人类回合的真实批准；任务修改或准备重试后要重新批准。
- 通过官方 delegation helpers 继承组合和权限，不复制凭据。成员不能调用父会话没有或实现不同的工具，也不能再次调度团队；每个任务从主会话原始工作区根目录开始。
- 写入范围是协作/调度约定，**不是文件系统沙箱**。停止不能撤销已有外部操作；没有自动 worktree、合并或回滚。
- 并发上限按团队计算，多个主会话可并行运行更多模型。单团队最多 12 成员、200 任务、500 消息；默认任务超时 20 分钟，结果快照最多保留 50,000 字符。
- 配置指令、会话任务、消息及结果可能敏感，遵循宿主数据保护方式，不提供额外加密。不要粘贴密钥。正常完成不等于独立审查已通过。

## 暂不包含

外部角色市场、每成员高级采样参数、自动工作树隔离/合并、团队归档删除 UI、同一主会话多轮独立团队历史管理、跨机器调度。

仓库保持 `private: true` 和 `UNLICENSED`，不会发布到 npm；公开发布前需明确许可证与发布策略。
